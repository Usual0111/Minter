# Home: сеансы CR (демо)

Home заменён на ограниченные сеансы CR. Используется существующий точный баланс (целые центы CR), история, локализация, SQLite, cookie-сессия, CSRF и Idempotency-Key. Nodes, Tasks, Friends и Wallet сохранены. Существующие экспедиции и DATA не удалены; это отдельная прежняя система в Nodes. Покупка оборудования пока не меняет фиксированную награду нового сеанса Home — правило такого влияния не задано.

## Демо-настройки

`assets/cr-session-system.js`, объект `defaults`: 50 минут, 100 центов CR базовой награды, 25 центов рекламного бонуса, 2 бесплатных и 2 рекламных запуска в сутки UTC на аккаунт, не меньше 4 минут перед предложением бонуса. Общие рекламные лимиты проекта продолжают действовать. Недельная цель — получить награды 5 завершённых сеансов, с понедельника UTC; отдельная награда за цель не выдумана. Ежедневная награда берётся из текущих настроек игры.

Настройки копируются в `state.crSessions.settings`. Новые значения defaults применяются к новым профилям. Для существующего профиля изменение серверных настроек требует явной миграции его settings. Длительность, база и размер потенциального бонуса сохраняются в сеансе; старый сеанс не меняет условий. Демо-время можно продвинуть через меню → Управление демо (+1 мин, +10 мин, +1 час).

## Сохранение и расчёты

Сеансы хранятся в состоянии аккаунта, сохраняется вся история. На одну галактику допускается один активный или неполученный сеанс. Суточные лимиты общие для всех галактик. Источник времени в серверном демо — сервер, клиент отображает его через performance.now(). В локальном HTML — явно обозначенное браузерное демо, зависящее от локального времени и localStorage.

Базовое накопление линейное, отображается до 4 знаков CR с округлением вниз. Бонус не меняет прошедший прогресс и не увеличивает базовое накопление; после подтверждения он добавляется к итоговой сумме, доступной в конце. Баланс меняется только при Collect. Claim не требует рекламы и не запускает следующий сеанс.

Запуск/сбор сериализуются BEGIN IMMEDIATE. Повторный запуск возвращает существующий сеанс, повторный сбор не начисляет повторно. Идентификатор операции `session-claim-<id>` защищён уникальностью `user_id,type,source` в ledger. Чужой ID не находится в состоянии аккаунта. Существующая таблица mining_requests возвращает результат после потери ответа.

Если сеанс завершился во время рекламы, сбор ждёт подтверждения, отмены или истечения рекламной сессии. Подтверждённый в срок бонус включается в итог. Отмена и ошибка не стирают прогресс.

## Интеграция

Типизированный контракт: `assets/cr-session-contract.d.ts`.
Демо использует существующие API `/api/mining/state` и `/api/mining/action`:
- `sessionStart`;
- `sessionClaim` с sessionId;
- `adStart` с purpose sessionStart/sessionBonus (для бонуса sessionId);
- `adConfirm` / `adCancel` с ID рекламной сессии.

Это НЕ реальные рекламные подтверждения и НЕ реальные выплаты. В demo adConfirm проверяет тестовый таймер и состояние запроса. Включение production по-прежнему запрещено сервером.

Для production нужны: реальные продуктовые лимиты/награды, проверенный Telegram initData в боевом развёртывании, рекламный SDK и подписанные серверные callbacks с защитой от replay/no-fill, production-адаптер по контракту и платёжный провайдер для реальных выплат. Пользовательский клик «реклама закрыта» не должен разрешать начисление.

## Проверка

`npm test` — экономика, восстановление, границы времени, повторный запуск/сбор, SQLite, отмена/ошибка/истечение рекламы, бонус на границе конца сеанса, лимиты и состояния Home. `npm run build` обновляет public, `npm run package` — автономный HTML.

Home прокручивается на коротких экранах, основной CTA 52 px, навигация не меньше 44 px, нижний padding учитывает её высоту. Отступ устройства берётся как max(CSS env, Telegram safeAreaInset.top), отступ контентных элементов Telegram учитывается отдельно один раз. Реальные нативные кнопки Telegram не рисуются. Проверка в браузере не заменяет проверку Mini App на iPhone/Android.

### Результат проверки сборки

87 автоматических проверок пройдены. В браузерном серверном демо проверены 360×740, 390×844, 430×932 и 360×600 CSS px: горизонтального переполнения нет, кнопка 52 px не перекрыта нижней навигацией. Проверены бесплатный запуск, рост счётчика, Collect +1 CR, обновление недельного счётчика, бонус +0.25 CR, сохранение бонуса после перезагрузки, русский язык. Ошибок в консоли при этих сценариях не обнаружено. Нативный Telegram на устройстве в этой проверке не использовался.
